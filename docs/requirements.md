# PocketCam 需求文档：Android 网络摄像头与 frpc

> 文档状态：首版需求基线（Draft）  
> 日期：2026-11-01  
> 产品名称：PocketCam（暂定）

## 1. 产品目标与用户场景

PocketCam 将 Android 手机作为网络摄像头使用。用户可在局域网内观看手机摄像头的实时视频，也可配置内置 frpc，将本机视频服务映射到远端访问。首版优先完成稳定的视频服务、清晰的服务状态和可用的 frpc 连接流程；灯光、录制、RTSP 等能力分阶段增加。

### 目标用户与主要场景

- 用户将旧 Android 手机放置在固定位置，作为简易网络摄像头。
- 用户在同一局域网中的浏览器或 MJPEG 客户端访问手机的视频流。
- 用户配置自己的 frps 服务器，通过 frpc 从外部网络访问摄像头服务。
- 用户在断网、权限拒绝或服务启动失败时，能够看懂问题并采取下一步操作。

### 首版目标

1. 在 API 17–25 的目标设备上启动和停止摄像头流服务。
2. 提供 HTTP 网页入口与 MJPEG 流，并要求访问凭据。
3. 将 frpc 内核打包在应用内；无需从应用外下载安装 frpc。
4. 提供简单配置向导和完整 TOML 配置入口，并展示 frpc 的连接状态与错误。
5. 保留可选的摄像头服务开机自启；开机恢复行为不得造成用户不知情的公网映射。

## 2. 当前原型与差距

以下现状依据当前仓库代码和 README 整理；“已存在”不代表已完成 API 17–25 的设备验收。

| 能力 | 当前原型 | 首版要求 |
|---|---|---|
| Android 项目 | Java app，`minSdk 17`、`targetSdk 24`、`compileSdk 36` | `minSdk 17`、`targetSdk 25`；不设置 `maxSdkVersion` 硬上限 |
| 摄像头采集 | 使用旧版 Camera API，以后台服务采集预览帧 | 保留 API 17 可用的采集路径，并覆盖 API 23+ 运行时权限 |
| 视频输出 | HTTP 8080；`/` 为简易网页，`/stream.mjpg` 为 MJPEG | 保留地址和协议，并增加认证、状态反馈和明确错误 |
| 服务控制 | 主页面提供启停按钮；以偏好设置记录服务状态 | 状态必须反映真实服务状态，启动失败时不能显示为运行中 |
| 开机自启 | 已有用户可选的开机接收器 | 保持默认关闭；用户开启后恢复摄像头服务，并报告恢复失败 |
| 分辨率 | 已有支持尺寸读取、选择和保存界面；配置在下次启动服务时生效 | 作为后续增强项；当前能力可保留，不作为首版验收阻塞项 |
| frpc 配置 | 已有服务器地址、端口、Token、远端端口及完整 TOML 文本编辑和本地保存；完整 TOML 优先 | 补齐文件导入、内核校验、启停、状态、错误和重连行为 |
| frpc 内核 | 尚未集成；现有页面保存配置后不会建立连接 | 集成并随应用打包，不依赖外部 frpc 安装 |
| 认证 | 当前视频流未认证 | 网页入口与 MJPEG 流均须认证 |
| 权限与错误 | 当前页面没有 API 23+ 摄像头运行时授权流程；相机和端口错误主要写入日志 | 权限请求、拒绝处理、端口冲突和服务失败均有用户可见反馈 |
| 应用内预览 | 当前没有预览画面 | 规划为后续功能 |

> README 中关于分辨率页面和 frpc 配置编辑的描述与当前源码不完全一致。后续维护时应以实际构建版本为准，并同步更新 README。

## 3. 首版功能需求

### 3.1 摄像头与 MJPEG 服务

- 用户可从主页面启动和停止摄像头服务。服务运行时保持前台通知，通知可返回主页面。
- 默认使用设备支持的低分辨率预览尺寸；当前默认请求 `320 × 240`，设备不支持时按当前回退策略选择可用尺寸。首版不要求新增分辨率调节能力。
- HTTP 服务默认监听 TCP 8080，并保留以下地址格式：
  - 网页入口：`http://<设备局域网地址>:8080/`
  - MJPEG 流：`http://<设备局域网地址>:8080/stream.mjpg`
- 主页面显示服务状态、本机可访问地址及视频流地址。若无法确定局域网地址，应显示明确提示，并允许用户手动确认网络连接状态。
- 摄像头服务退出或启动失败后，UI 状态、前台通知和持久化状态须同步；不可仅根据先前保存的布尔值显示“正在运行”。
- 同一时间由本应用管理一个本地摄像头流服务。客户端断开不得导致摄像头服务退出。
- 默认只在用户主动启动时开放服务。开机自启默认关闭；开启后只恢复本地摄像头服务。首版不默认自动启动 frpc 公网映射。

### 3.2 权限与系统兼容

- 安装最低版本为 Android API 17。`targetSdk` 设为 API 25，API 17–25 纳入首版兼容验收。
- 不设置 `maxSdkVersion=25`。API 25 是首版目标和兼容验收范围上界，不代表应用主动禁止更高 API 安装。`targetSdk` 与 `maxSdkVersion` 含义不同，见 [Android `<uses-sdk>` 文档](https://developer.android.com/guide/topics/manifest/uses-sdk-element)。
- API 23 及以上在访问摄像头前请求运行时 CAMERA 权限。用户拒绝时解释所需权限、保持服务停止，并提供重新请求入口；不得因缺少权限直接崩溃。
- API 17–22 使用系统安装时授予的权限行为，不调用不存在的运行时权限 API。
- 服务、通知、开机广播、网络状态读取和相机释放均按 API 17–25 的系统行为实现；高版本专有 API 必须检查版本并提供兼容路径。

### 3.3 访问认证与安全提示

- 用户可设置或更新视频访问凭据；网页入口和 `/stream.mjpg` 都拒绝缺少或错误凭据的请求。
- 认证方式须兼容首版目标浏览器及常见 MJPEG 客户端；验证通过后才能发送网页内容或视频帧。
- 视频访问凭据保存在应用私有配置中，不写入应用日志、frpc 日志或崩溃诊断信息。应用已禁用备份的设置应继续保持，避免凭据随系统备份导出。
- 首次启用 frpc 公网映射时显示风险提示：公网 HTTP 访问可能未加密，认证本身不代表视频和凭据在所有网络链路上受到加密保护。用户确认后允许继续。
- 风险提示须可在 frpc 设置中再次查看；配置已保存不代表公网连接已启动。
- 首版不强制 HTTPS，也不宣称 frpc 已为观看端到公网服务器的链路提供 TLS。

### 3.4 frpc 集成与生命周期

- 首选将 frpc Go 实现封装为应用内 Android AAR/共享库，由 Java 层调用；wrapper 和 AAR 可由本项目自行维护、构建。
- 建议的 Java-facing wrapper 能力：
  - `start(config)`：加载配置、校验并启动 frpc 实例。
  - `stop()`：停止当前实例并释放网络和后台资源。
  - `getStatus()` / 状态回调：报告 `stopped`、`starting`、`connected`、`reconnecting`、`error` 等状态及简短说明。
  - 日志回调或读取接口：提供经过脱敏的诊断信息，不返回 Token、视频凭据或完整敏感配置。
- AAR 方案可使用 gomobile 生成 Java 绑定和 Android 共享库；gomobile 的 Android AAR 构建下限为 API 16，但这不证明 frpc 依赖本身能在 API 17 运行。必须在真实或等效 API 17 设备上验证。参考 [gomobile 文档](https://pkg.go.dev/golang.org/x/mobile/cmd/gomobile) 和 [Go mobile 绑定实现](https://github.com/golang/mobile/blob/master/cmd/gomobile/bind.go)。
- 发布包至少包含面向目标设备的 ARM 32 位和 ARM 64 位原生库；具体 ABI 以实际旧设备和发行渠道为准。调试构建可额外包含 x86/x86_64 模拟器 ABI。
- 用户分别控制摄像头服务与 frpc 映射。frpc 映射启动前确认本地摄像头服务可用；停止摄像头服务时，停止或报告失效的本地代理，避免 UI 继续显示有效映射。
- 在网络短暂中断或服务端暂不可用时，frpc 应按内核支持的策略重连；UI 展示重连状态。用户主动停止后不得继续重连。
- 保存配置、启动内核和成功建立代理是不同状态，界面不得将“配置已保存”显示为“已连接”。

### 3.5 frpc 配置

#### 摄像头映射向导

- 配置服务器地址、服务器端口、认证 Token 和远端映射端口。
- 默认服务器端口为 7000，默认远端映射端口为 8080；两者均可修改并验证为 1–65535 的整数。
- 向导生成一条 TCP 代理，将手机本机 HTTP 服务端口 8080 映射到用户设置的远端端口。
- 服务器地址不能为空；字段错误应定位到对应输入项，不启动 frpc。

#### 完整 TOML 配置

- 用户可粘贴或编辑完整 TOML，并可从设备文件导入 `.toml` 配置。
- 选择完整 TOML 模式时，以该配置为准；向导字段保留但不覆盖完整配置。
- 完整配置交给匹配版本的 frpc 内核校验，不要求应用自行实现全部 frpc 配置语法。
- 校验失败时展示可读的错误信息；不得因校验失败而丢失用户当前编辑内容。
- 高级配置保存后须清楚标识当前生效来源，避免用户误以为向导字段仍在生效。

#### 配置与凭据存储

- 配置保存在应用本地，用户可查看当前模式并重新编辑。首版不要求云同步。
- 敏感字段不出现在普通日志或 UI 调试输出中；Token 与视频访问凭据不得被复制进错误报告。
- 原型配置迁移应保留现有键值（服务器、端口、Token、远端端口、TOML），但新字段应有明确默认值。

## 4. 状态、异常与恢复

| 场景 | 预期行为 |
|---|---|
| 用户未授予摄像头权限 | 不启动摄像头或 HTTP 服务；解释权限用途并提供重新请求入口 |
| 设备没有可用摄像头或相机被其他应用占用 | 服务启动失败；释放已获取资源；显示相机不可用或被占用的提示 |
| 端口 8080 已被占用 | 启动失败并显示端口冲突；不显示有效访问 URL；允许用户停止冲突服务后重试 |
| 相机或 HTTP 服务启动异常 | 状态进入错误；停止前台服务并释放 Camera、Socket、SurfaceTexture 和工作线程 |
| 无可用 IPv4 局域网地址 | 服务状态与地址状态分开显示；不构造误导性的可访问地址 |
| 请求不带认证或认证错误 | 返回未授权结果，不发送 HTML 页面或视频帧 |
| frpc TOML 无效 | 不启动内核；显示校验错误并保留配置供修改 |
| frpc 服务端地址、端口或 Token 错误 | 状态进入错误或重连；给出脱敏的连接失败原因 |
| 网络中断 | 保持本地服务状态；frpc 显示重连；网络恢复后按策略恢复代理 |
| 用户停止 frpc | 关闭代理并停止自动重连；摄像头本地流可继续运行 |
| 用户停止摄像头服务 | 释放摄像头与 HTTP 端口；关联的 frpc 摄像头代理停止或显示失效 |
| 开机自启恢复失败 | 不循环快速重启；记录脱敏错误，并在用户打开应用时展示状态 |

## 5. 后续迭代路线

以下项目不阻塞首版，但应作为后续版本的独立需求评估：

1. **摄像头控制：**改善分辨率选择、帧率/画质设置、前后摄像头选择及设置即时生效能力。
2. **设备灯光：**支持设备具备闪光灯时控制补光灯，并处理硬件不支持和相机占用状态。
3. **录制：**本地视频录制、存储位置、磁盘空间不足和录制状态提示。
4. **RTSP：**提供 RTSP 输出能力及与 MJPEG 服务的资源协调策略。
5. **控制 API：**提供受认证保护的远程状态查询与控制接口，并定义 API 版本和兼容策略。
6. **应用内预览：**在不影响后台采集稳定性的前提下显示预览画面。

## 6. 验收标准

### 构建与兼容

- Gradle 构建成功；最终 manifest 的 `minSdkVersion` 为 17、`targetSdkVersion` 为 25，且没有 `maxSdkVersion=25`。
- 对 API 17–25 执行兼容检查；API 17、23、25 作为关键端到端验收版本。API 23 必须覆盖权限首次请求、允许和拒绝路径。
- 在 API 17 与 API 25 设备或等效测试环境验证内置 frpc AAR 的加载、启动、持续运行和停止；结果记录设备 ABI、Android 版本、frpc 版本及配置类型。
- API 17 测试至少覆盖 ARM 32 位目标；API 25 覆盖实际计划发布的主要 ABI。

### 摄像头流

- 启动服务后，主页面和前台通知显示运行中；停止后显示停止并释放端口。
- 已认证浏览器能够打开 `/` 并查看实时画面；MJPEG 客户端能够连接 `/stream.mjpg`。
- 缺少或错误凭据不能读取页面或视频帧；正确凭据可访问两个路径。
- 验证摄像头权限拒绝、相机被占用、端口冲突、网络地址不可用及服务异常的提示和资源清理。
- 验证用户关闭并重新打开应用时，界面状态与服务真实状态一致。

### frpc 与配置

- 向导配置可连接测试 frps，并从远端访问摄像头本地 HTTP 服务。
- 无效地址、端口、Token 和 TOML 均有错误反馈；配置文本不会因失败而清空。
- 完整 TOML 模式优先于向导字段；验证文件导入、保存、重新打开及内核校验。
- 验证断网后的重连、用户主动停止后的不重连、服务端认证失败和摄像头服务先停后的代理状态。
- 首次启用远程映射显示明文传输风险；凭据和 Token 不出现在普通日志或错误信息中。

### 稳定性

- 在 API 17 和 API 25 的代表设备上进行至少 30 分钟持续预览与单客户端观看，确认无崩溃、明显资源泄漏或无法停止的问题。
- 多次启停服务及 frpc 后，相机、端口、原生线程和通知均可释放；重复操作不得产生多个代理实例。

## 7. 需求边界与决策记录

- 参考 shenyaocn 的“IP摄像头”用于确定产品方向；PocketCam 首版不要求与参考应用功能齐全或 UI 一致。
- 首版目标是 Android API 17–25 兼容验收，不代表 API 25 以上的设备被禁止安装，也不承诺所有更高系统版本均已验证。
- 首版公网访问要求有认证并展示 HTTP 明文风险；HTTPS 强制、证书管理和端到端安全配置不在首版范围。
- frpc 优先以 AAR/共享库集成；是否采用 gomobile、具体 frpc 版本和 wrapper 内部实现，以 API 17 的真实构建与运行验证为准。
- 本文是需求基线，不代表文中所有功能均已实现或通过设备验证。每次发布应记录通过的 API 版本、设备型号、ABI、frpc 版本和未覆盖场景。
